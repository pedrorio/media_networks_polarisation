# Design

## Context

See proposal.md. The sed redirection is `sed 's/<[^>]*>//g ; /^$/d' "$file" > "$file"`. The raw paths are never written.

## Goals / Non-Goals

**Goals:**

- Clean output equals the jq documents with tags stripped.
- A documented command fills `data/raw` for that jq shape.

**Non-Goals:**

- Changing who counts as a text author inside jq.
- Connecting the file ETL to the Kafka crawl.
- Implementing this in the current pull request.

## Decisions

- Write sed to a temporary file and move it into place, so the redirection cannot truncate the input. Alternative considered: `sponge`. Rejected because it is an extra package and a temp file is enough.
- The raw-file command shells out to the existing HTTP helpers and writes the jq field names (`titulo` / `nome` for Público, `fullTitle` / `metadata` for Observador). It is not a download of a frozen archive, because no archive exists. Tests use the checked-in fixture and do not call the network.

## Risks / Trade-offs

- [Live sites change or block the fetch] → the command's failure is visible, and the golden tests keep using fixtures. The requirement is the file shape, not that today's homepage is stable.
- [HTML strip is a regex] → it matches the sed expression already in the script. A real HTML parser is out of scope.

## Migration Plan

- Replace the two scripts in place. Existing empty clean files are regenerated by re-running the script. No data migration.
